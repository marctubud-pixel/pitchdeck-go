# C · 比稿作战室

> 24 小时交付出一个能提报的比稿方案。

## 是什么

一个以「比稿项目」为单位的工作台：

```
接单 → 判断 → 情报 → 策略 → 验收 → 交付 → 复盘
```

不是聊天 Bot。AI 做案头工作，人做判断。

## 北极星指标

| 指标 | 目标 |
|---|---|
| 交付时间 | 24 小时内 |
| 单项目成本 | < ¥50 |
| 单项目人时 | < 6 小时 |

## v0.1 范围

- **F1 接单卡**：brief → 任务书 + 反问清单
- **F2 启动包**：执行总监产出论点 / 模块 / 骨架 / 工时 / 风险 / 不确定项
- **F3 策略卡 ×3**：三个方向，带证据、带预算量级
- **F4 验收 + 存档**：检查清单 + 复盘卡

明确不做：创意生成、媒介排期、自动出 deck、先例自动检索、多用户权限、计费。

## 仓库结构

```
.
├── docs/
│   ├── architecture.md        # v0.1 架构
│   ├── PRD-v0.1.md            # 产品需求文档（撰写中）
│   └── decisions/             # 架构决策记录（ADR）
├── prompts/                   # Agent prompt 骨架
├── app/                       # 应用代码（v0.1.5 开始）
└── data/                      # 客户资料与生成物（gitignore，不入库）
```

## 数据与保密

客户 brief、原始素材、生成的 deck 一律放 `data/`，**不进仓库**。
仓库只放代码、文档、prompt、模板。
