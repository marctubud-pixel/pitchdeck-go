# 0004 · 每阶段验收 + 多模型生产通道

- 状态：已接受
- 日期：2026-11-12
- 补充：`0002-six-gates.md` 的 D9（F4 验收官）

## 背景

两个反馈：

1. 原型只在最后有一个「验收」。但真实交付里，策略错了就不该进生产——**审查必须在每个阶段收口，而不是最后一次性兜底。**
2. 生产不该只有文字。KV、海报、短视频、配音都要出，意味着要接多个模型。

## 决策

### D12 · 三审分离，各管一段

| 角色 | 回答的问题 | 何时跑 | 权力 | 输出 |
|---|---|---|---|---|
| **验收官** | 做**对**了吗？全不全？ | 每个阶段结束 | 打回权，最多 2 轮 | Pass / Fix / Redo + 可执行指令 |
| **评审官** | 能**赢**吗？会被问倒吗？ | 策略、终稿 | 只给判断，无打回权 | 胜率评估 + 漏洞清单 + 答辩 Q&A |
| **合规扫描** | 踩线没有？ | 生产、终验 | **阻断** | 红线 / 警告 / 通过 |

**验收官不评价「好不好」，只评价「对不对、全不全」。** 好不好是评审官和总导演的事。这条边界必须守住，否则验收会退化成第二个评审，两个都变得不可信。

**每个阶段的验收清单不同**，但都遵循同一个形状：3–5 条可勾选的客观项 + 一条「不通过时改什么」。

### D13 · 阶段验收放在闸门之前

顺序固定为：`阶段产物 → 验收官 → 人工闸门`。

理由：闸门是人的决策，人不该替 AI 检查格式。**先让机器把「完整性」查完，人只看「方向」。** 这样 G2 那张卡上的信息量才是决策，不是校对。

例外：验收不通过时，闸门不开放——不是「让人决定要不要放行」，是「先修好再说」。

### D14 · 生产走多模型，但 v0.1 只接两条通道

生产的资产类型和通道：

| 资产 | 通道 | v0.1 接不接 |
|---|---|---|
| 文案 / 脚本 / 策略文本 | 文本模型（Claude / DeepSeek / Qwen） | ✅ |
| KV / 海报 / 配图 | 图像模型（Seedream / GPT Image） | ✅ |
| 短视频成片 | 视频模型（Seedance / Kling） | ❌ 留接口，v0.2 |
| 配音 | TTS（火山 / 讯飞） | ❌ 留接口 |
| Deck 排版 | 模板引擎（python-pptx） | ✅ |

**为什么不一上来接五个模型：** 每条通道都要处理失败、重试、计费、版权、一致性。先跑通「文本 + 图像 + 排版」，视频和配音等有真实单子要求再接。

**架构要求：** 所有通道走同一个 `generate(asset_type, prompt, refs)` 接口，模型可替换。换模型是配置，不是改代码。

### D15 · 生产是「AI 出活 + 人提意见」的循环

- AI 按已确认的策略和骨架出 v1，一次出全部资产。
- 人只提**具体意见**（哪一项、改成什么），不提「感觉不对」。
- 只重跑受影响的项，不整包重来；未涉及的项标「未改动」。
- 循环到人满意为止，不设轮次上限；但每轮的成本记在项目账上。

## 后果

- PRD 第 5 节每个功能增加「阶段验收清单」；第 6 节 `Critique` 实体区分 `stage` 与 `type(qa|critic|compliance)`。
- 原型每个阶段加一条验收带，S6 改名「终验」。
- 成本模型要按通道分别计（文本 / 图像 / 排版），否则单项目 <¥50 无法核算。
