# 0005 · 九步五闸：接单与判断合并，重命名两站

- 状态：已接受
- 日期：2026-11-12
- 修订：`0002-six-gates.md` 的 D8（闸门 6 → 5）
- 前置：`0004-stage-review-and-models.md`（每阶段验收）

## 背景

走原型时发现三处不顺：

1. **接单和判断是同一件事。** 没读懂 brief 就没法判断该不该接，分成两屏、两道闸，人要做两次确认，第二次确认的信息还是同一批。
2. **「启动包」这个词是内部黑话。** 用户说不出口，客户也不关心。
3. **「情报」听起来像情报机构。** 它实际做的事是市场、竞品、人群、平台调研。

## 决策

### D16 · 九个状态，五个闸门

```
S0 接单·判断 → S1 启动 → S2 调研 → S3 策略 → S4 生产 → S5 合稿 → S6 终验 → S7 交付 → S8 复盘
     G1           G2                      G3                    G4                    G5
```

- S0 合并原 S0 接单 + S1 判断，G1 一次性解决「任务书对不对 / 接不接 / 报多少」。
- 报价是**人输入的字段**，机器只给区间，不进入任何自动规则。
- 闸门 6 → 5：G1（接单·判断）· G2（启动）· G3（策略）· G4（合稿定稿）· G5（复盘）。

### D17 · 改名

| 原名 | 现名 |
|---|---|
| 启动包 | **启动** |
| 情报 | **调研** |
| 验收（唯一一处） | **终验**（S6） |

「验收」这个词保留给**每阶段都跑的那个角色**（验收官）。S6 是整份稿子的终验，不是唯一一次验收。

### D18 · 生产的产物是多模态，不只是文字

生产阶段输出四类资产：KV / 海报、脚本与文案、KOL 组合、内容日历。通道见 ADR 0004 的 D14。
人在这里只做两件事：给具体修改意见、确认收敛。

### D19 · 合稿由 AI 拼装，人只处理「不一致」

AI 按骨架拼装并标出前后矛盾（通常 3 处以内），人确认或推翻。**不要求人在这一步做审美判断**——审美留给 G4。

## 后果

- PRD 第 0–4 节需整篇重写（闸门数、步骤名、验收位置都变了），与第 5–8 节一起出 v0.2。
- 原型同步：`prototype/flow.html` 已按此实现。
- 阶段验收的清单写进 PRD 第 5 节每个功能，作为「验收标准」的一部分。
