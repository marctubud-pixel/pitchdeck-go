# 0002 · 六个闸门与五个功能

- 状态：已接受
- 日期：2026-11-12
- 修订：`0001-v0.1-scope.md` 的 D2、D4

## 背景

0001 定的是「4 个功能 + 5 个闸门」。写 PRD 时发现两处不对：

1. **启动包没有闸门。** D4 要求执行总监出启动包后人再拍板，但 5 个闸门里没有它的位置——G3 被放在策略卡之后。结果是「论点 / 模块 / 骨架」这一层最贵的决策无人确认，直接进策略，方向错到 60 页才被发现。
2. **验收和存档是两件事。** 验收官每个阶段都跑、有打回权；复盘存档只在项目结束后跑一次、是数据飞轮的入口。合并成一个功能后，两边的验收标准互相打架。

## 决策

### D8 · 启动包后加一道闸门，闸门总数 5 → 6

顺序：`G1 接单 → G2 接不接 → G3 启动包 → G4 策略 → G5 定稿 → G6 复盘`

- G3 是 v0.1 最重要的一道闸。前面的可以快，这一道必须让「未决问题」显性化。
- G3 的放行只看启动包里有没有 A 类未决问题，**不看预算、不看案例数、不看置信度**（见 D11）。
- 情报放在启动包之后：先圈定查什么，再花钱查。情报推翻论点时启动包升 v2，**不重开闸门**。
- 启动包在 v0.1 一律由人确认；「快速通过」只是减少阅读量，不跳过。

### D11 · 放行规则改为「未决问题」驱动

原设计按「预算 + 相似案例数 + 模型置信度」三级放行。三样都撤：

| 原触发器 | 撤销理由 |
|---|---|
| 预算 20 万 / 80 万 | 商业判断，是人的事；机器只把预算原样带到 G2 |
| 相似案例数 | v0.1 档案只存不取，恒为 0，等于永远走人工 |
| 模型置信度 | 自评、不可校准、不可执行；0.76 不告诉你该看哪一页 |

改为按未决问题分类：

- **A 类**（不回答没法继续，必须人拍板）→ 必须人工，且必须写成可被一句话回答的问句。
- **B 类**（已定，只通知改动）/ **C 类**（假设，错了再改）→ 快速通过。
- **零条未决** → 视为失败打回。没有未决问题说明它在装懂。

合规命中（医疗 / 金融 / 未成年人 / 绝对化用语）不是升级，是**阻断**。

### D9 · 功能从 4 个拆成 5 个

`F1 接单卡 · F2 启动包 · F3 策略卡 · F4 验收官 · F5 复盘存档`

- F4 只回答「做对了吗、全不全」，有打回权，最多 2 轮。
- F5 在 v0.1 只存不取；先例检索仍是 v0.2 的事。
- 功能数增加，但**没有增加新能力**——只是把原来混在一个功能里的两件事说清楚。

### D10 · 策略卡的定位改为「降返工」，不是「替代 deck」

客户最终付费的仍是 deck。策略卡的价值是让方向在 3 页纸内被否掉，而不是在 60 页之后。
如果试点显示客户不愿看策略卡、只要成品，H2 失败，策略卡退回为内部产物。

## 后果

- PRD 第 0、1.3、2.2、3.3、4.x 节同步修订。
- v0.1 的人工负担增加一个确认动作（G3），但预期减少一次 20 小时级别的返工。
- 如果 G3 在 10 单里从未拦下过错误，说明这一层判断本身价值不足——届时合并回 G2，不硬留。
