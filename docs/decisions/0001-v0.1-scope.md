# 0001 · v0.1 范围与产品形态

- 状态：已接受
- 日期：2026-11-12

## 背景

方向已收敛为「比稿作战室」。需要固定 v0.1 的边界，避免做着做着变成通用生成器。

## 决策

### D1 · 产品形态是工作台，不是 Bot

比稿是项目，不是对话。产品以「项目」为单位：状态机 + 产物 + 闸门 + 档案。
聊天只作为入口，不作为核心交互。

### D2 · v0.1 只做四个功能

F1 接单卡、F2 启动包、F3 策略卡、F4 验收 + 存档。
创意生成、媒介排期、自动出 deck、先例自动检索、多用户权限、计费全部不进 v0.1。

### D3 · 媒介是可选模块，不是固定阶段

由执行总监按 brief 选择。部分比稿（品牌策略、创意比稿、视觉案）不需要媒介。

### D4 · 执行总监先出启动包，人再拍板

AI 负责「把该想的想到、该分的分好、该问的问出来」；人负责「拍板」。
启动包必须包含至少两条「不确定项」。

### D5 · 验收官与评审官分离

验收官回答「做对了吗、全不全」，有打回权；评审官回答「能赢吗、会被问倒吗」，只给判断。

### D6 · 档案 v0.1 只存不取，但字段按可检索设计

先例检索放 v0.2。v0.1 的 `Outcome` / `Playbook` 字段必须支持将来的向量检索与结构化过滤。

### D7 · 第一个垂直行业：服装 / 时尚 + 电商

理由：需求高频（上新、大促、季节 campaign）、有现成客户资源、案例可复用。

## 后果

- v0.1 可以用飞书多维表格 + 现成模型先跑通，不急着写代码。
- 先例检索的缺失是已知债务，v0.2 必须补。
- 如果服装行业 90 天内跑不出 2 个付费客户，重新评估垂直行业，而不是改产品形态。
